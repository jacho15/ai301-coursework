# Rubric: is this pull request ready to submit?

## Checks

| Check | Evidence | Pass condition | Weight |
|---|---|---|---|
| Diff stays inside the plan | Each hunk in the diff, checked against the plan's files, approach, not-in-scope line, and deviation notes. | Pass if every file changed is one the plan names (tests, changelog, or docs the plan or repo asks for are fine too) and every hunk does what the approach or a deviation note says. Fail if a hunk touches a file the plan never mentions or adds something the plan doesn't. Stuff like rewriting other code, a new flag, renaming things, or rewording unrelated text, even inside a planned file. What the description says about scope doesn't matter here. | required |
| Plan delivered and description truthful | The plan's promised steps and the title and description's claims, each found in the diff. | Pass if every promised step is in the diff, or the plan defers it and the description says so too, and everything the title or description claims is actually in the diff. Fail if a step is missing and both places don't explain it, or the description claims something the diff doesn't have. Stuff like a docs update, a test, or "exactly as planned" when it isn't. | required |
| Test evidence re-runs the plan's test plan | The test evidence, checked one item at a time against the plan's test plan and the repro steps. | Pass if each repro from the repro evidence is run again on the changed code with a before and after you can see (output, an error, or an exit code). Everything else in the test plan (controls, extra cases, smoke checks, the suite) just needs to be named with its result, like "`go test ./...` passes". Fail if a repro just says it works ("tested locally", "works now"), the suite result has no command named when the test plan asks for it, the run goes through something the diff didn't change, or anything the test plan names is left out completely. | required |
| Diff is free of debris | Each hunk in the diff, plus the commit list. | Pass if every hunk is the fix, its tests, comments about it, or something the plan or repo asked for. Fail if a hunk has a debug print, commented-out code, a function nothing uses, a leftover TODO, or reformatting or import changes the fix doesn't need. | required |
| Repo's stated asks are met | The repo facts block's PR template asks, contribution asks, and AI policy, checked against the description and diff. Live, use the PR template, CONTRIBUTING.md, AI policy, and the house rules in `scope.md`. | Pass if everything the template or contribution guide asks for is there and filled in (like an issue reference, a changelog or whatsnew entry, or named sections), and the description discloses AI use if the policy requires it. Fail if a stated ask is missing, left as boilerplate, or contradicted, or if required disclosure isn't there. If the repo has no template or AI policy, only its other stated asks count. | required |

## Verdict rule

Accept only if every required check passes. A fail or unclear on any required check means reject. Unclear counts as fail since a claim the package can't back up isn't ready. There are no preferred checks. A shortfall that the plan records and the description mentions doesn't fail any check.
